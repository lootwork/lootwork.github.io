О команде

We are looking for an experienced software engineer to join our System Security team and build the tools and platforms that make secure software delivery the default, starting on the developer's machine. You will work across the full path code takes, from local development through source control, dependencies, and CI/CD to production artifacts, and make sure that only trusted code, built by trusted pipelines, reaches production.

Security starts where code is written. You will shape the local developer experience: the CLIs, Git workflows, package managers, dev environments, IDE integrations, and AI coding assistants engineers use every day. Your job is to make that toolchain both fast and hardened. That means credentials that never need to sit on disk, dependencies that are vetted before they are installed, secrets caught before they are committed, and local tools that cannot be quietly turned against the developer. Done well, the secure path is also the fastest path, so engineers choose it on their own.

From there, you will carry the same principle through the rest of the chain. You will design pipeline templates and platform services that give every team secure defaults, and solve hard systems problems along the way: short-lived credentials and workload identity for every pipeline, trusted dependencies, and artifact integrity from build to deploy. Strong security guarantees have to coexist with low latency, high reliability, and a developer experience engineers actually like.

You'll join at a time of high impact. Our delivery platform runs [X,000+] pipelines a day for [N00+] engineers across GitHub Actions, Jenkins, and an in-house CI. AI-assisted development and coding agents are increasing both the speed of delivery and the volume of change flowing through these systems, on laptops as much as in CI. Securing that without slowing engineers down takes strong engineering and great tooling, not more process.

Что предстоит делать

  • Build and own the developer CLI and local toolchain integrations, such as Git credential helpers and hooks, so that secure access to code and services is the default and the fastest option.
  • Harden the local development environment: vetted package installs, safe defaults for package managers, dev containers or reproducible environments, and controls for IDE extensions and AI coding assistants.
  • Shift security feedback all the way left: pre-commit secret and dependency checks that are fast, accurate, and easy to fix.
  • Build reusable, secure-by-default pipeline templates, plus a CLI that lets teams adopt them in minutes.
  • Design and build platform services that sit in the critical path of software delivery and are fast, reliable, and hard to bypass.
  • Bring OIDC workload identity and short-lived credentials to CI/CD, so that pipelines get only the access they need, only for as long as they need it.
  • Add signing, provenance, and SBOM generation to every build, and enforce verification and policy at deploy time.
  • Design dependency controls, such as proxies, pinning, and allow/deny policies, that block malicious and typosquatted packages without breaking builds.
  • Harden CI/CD against pipeline injection, untrusted third-party actions and plugins, and runner compromise.
  • Build security signals into the tools developers already use, including PR checks, CLI feedback, and clear fix guidance, so that problems are caught before merge.
  • Measure adoption and developer friction, and use the data to improve the paved path.
  • Partner with platform, infrastructure, and product teams, and take part in incident response.

Кого мы ищем

  • 5+ years of software engineering experience, with strong Go or Python (Rust or Java also welcome) and the ability to build and run production services on your own.
  • Experienced building developer tooling, internal platforms, or infrastructure that sits on the critical path of software delivery.
  • Strong understanding of how Git, GitHub, and CI/CD systems (GitHub Actions, Jenkins) work internally, including their trust boundaries and common attack paths.
  • Hands-on experience with at least one of: artifact or image signing, provenance/SBOM, OIDC workload identity, secrets management, or dependency security.
  • Familiar with a major public cloud, Kubernetes, and containers.
  • Product-minded: you design for the developer first, and you can drive adoption through good tooling rather than mandates.

We understand not everyone will meet every qualification on day one. If this work excites you, we encourage you to apply.
